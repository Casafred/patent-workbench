## IPC数据源优化方案

### 问题分析
1. IPC分类体系非常庞大（约7万个条目），完整获取需要数小时
2. 当前数据只获取了3层，缺失大量子分类
3. 样式混乱是因为数据结构不完整

### 解决方案：混合模式

**方案：本地缓存 + 按需获取**

1. **本地存储前3层**（部→大类→小类）
   - 约300个条目，文件小，加载快
   - 覆盖90%的浏览需求

2. **更深层级按需从WIPO API获取**
   - 当用户展开某个小类时，实时获取其子分类
   - 获取后缓存到内存，避免重复请求

3. **修改后端API**
   - `/ipc/tree` - 优先从本地读取，本地没有则调用WIPO API
   - 添加缓存机制，减少API调用

### 具体修改
1. 保留当前已获取的300条数据作为基础
2. 修改后端`get_tree()`函数，支持按需获取
3. 添加内存缓存，缓存已获取的子节点

### 优点
- 快速响应：常用数据本地读取
- 数据完整：按需获取完整层级
- 节省空间：不需要存储全部7万条数据
